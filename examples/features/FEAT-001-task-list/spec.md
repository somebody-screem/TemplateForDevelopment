## 目的と対象範囲

利用者が短い用事を追加し、済んだ用事を同じ画面で区別できるようにします。
対象は入力・一覧表示・完了切替です。ログイン・永続保存・削除・並べ替えは対象外です。
初期表示ではタスクが0件で、「タスクはありません」と表示します。
画面には「再読み込みするとタスクは消えます」と常時表示します。

## 用語

| 用語 | 意味 |
| --- | --- |
| タスク名 | 入力の前後の空白を除いた文字列。途中の空白は残す |
| 文字数 | Unicodeコードポイントの個数。結合文字や複合絵文字は複数と数える場合がある |
| 完了 | 利用者が済ませたと指定した状態。タスクごとに保持する |

## 要求

| 要求ID | 利用者に提供する振る舞い |
| --- | --- |
| EXAMPLE-FEAT-001-R01 | 追加ボタンで1〜100文字のタスク名を追加する。前後の空白を除き、空または101文字以上なら追加せず理由を表示する |
| EXAMPLE-FEAT-001-R02 | 同じ名前を複数回追加でき、それぞれを独立したタスクとして扱う。追加順に表示する |
| EXAMPLE-FEAT-001-R03 | 新しいタスクは未完了とし、タスクごとの操作で完了・未完了を切り替える |
| EXAMPLE-FEAT-001-R04 | 開いている画面のメモリにだけ保持する。再読み込み後は0件になり、その制約を画面に表示する |

## 受入条件

受入条件IDは、設計・作業・検証を同じ内容で結びつけるために使います。
「期待結果」はこれから満たすべき条件で、実施済みの結果ではありません。

| 受入条件ID | 種別 | 要求ID | 操作・前提 | 期待結果 |
| --- | --- | --- | --- | --- |
| EXAMPLE-FEAT-001-AC01 | 正常 | EXAMPLE-FEAT-001-R01 / EXAMPLE-FEAT-001-R03 | 0件の画面で `  牛乳を買う  ` を入力し追加する | `牛乳を買う` が未完了で1件表示され、入力欄が空になる。「タスクはありません」は消える |
| EXAMPLE-FEAT-001-AC02 | 異常 | EXAMPLE-FEAT-001-R01 | 空文字、半角空白だけ、全角空白だけの入力をそれぞれ追加する | 件数は変わらず「タスク名を入力してください」を表示する。入力内容は保持する |
| EXAMPLE-FEAT-001-AC03 | 境界 | EXAMPLE-FEAT-001-R01 | `あ` 100個、`あ` 101個をそれぞれ入力し追加する | 100文字は追加できる。101文字は追加せず「100文字以内で入力してください」を表示し入力内容を保持する |
| EXAMPLE-FEAT-001-AC04 | 正常 | EXAMPLE-FEAT-001-R02 / EXAMPLE-FEAT-001-R03 | `確認する` を2件追加し、後の1件を完了にしてから未完了に戻す | 同名の2件が追加順に残る。後の1件だけが切り替わり、前の1件は未完了のまま |
| EXAMPLE-FEAT-001-AC05 | 境界 | EXAMPLE-FEAT-001-R04 | 1件以上ある画面を再読み込みする | 0件になり「タスクはありません」を表示する。再読み込みで消える旨の説明は操作前後とも表示する |
