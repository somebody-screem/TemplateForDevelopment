# Codexで育てる開発プロジェクト

対話しながら試作する開発と、仕様を決めてから実装する開発の両方に使えるテンプレートです。文書は日本語、パスは用途がわかる英語に統一しています。技術スタックやアプリの実装はまだ決めていません。

## 最初に読むもの

| 知りたいこと | 読むファイル |
| --- | --- |
| 各文書には何が書かれているか | [文書一覧と依存関係](docs/README.md) |
| ファイルをどこに置き、どう名付けるか | [ファイルの整頓ルール](docs/guide/file-organization.md) |
| 試作・仕様・実装をどう進めるか | [開発の進め方](docs/guide/workflow.md) |
| 空欄を埋めて文書を作りたい | [テンプレート一覧とコピー手順](templates/README.md) |
| 完成した文書の書き方を見たい | [タスクリスト機能の記入例](examples/README.md) |
| Codexにどのルールを伝えるか | [Codex向け作業指示](AGENTS.md) |

## フォルダ構成

```text
.
├── README.md                   # 人間向けの入口
├── AGENTS.md                   # Codex向けの短い作業指示
├── docs/
│   ├── README.md               # 文書一覧・依存関係図
│   ├── guide/                  # 整頓ルール・開発手順
│   ├── product/                # 誰の何を解決するか・全体要件
│   ├── architecture/           # 全体の技術構成・共通制約
│   ├── features/               # 機能別の仕様・設計・作業・検証
│   ├── decisions/              # 選択肢と採用理由の記録（ADR）
│   └── archive/                # 廃止した文書と後継への案内
├── templates/                  # コピーして使う空欄付きの原本
│   ├── feature/                # spec / design / tasks / verification
│   ├── experiment.md           # 試作メモの原本
│   └── decision.md             # 意思決定記録の原本
├── examples/                   # 記入例。実プロジェクトの仕様ではない
├── experiments/                # 試作コードと試した結果
├── src/                        # 採用したアプリのコード
└── tests/                      # 採用したコードを確かめるテスト
```

各フォルダのREADMEも含めて配置済みです。`docs/features/FEAT-001-short-name/` などの個別機能フォルダは、着手する際に作ります。

## このテンプレートから始める

1. [目的と対象範囲](docs/product/vision.md)に「誰の・何の問題を解くか」を書く。
2. [全体要件](docs/product/requirements.md)に最初の成果と制約を書く。試作中は仮説と明記する。
3. 試作からなら[試作メモ](templates/experiment.md)、仕様からなら[機能テンプレート](templates/README.md)をコピーする。
4. 技術を選んだ時点で[全体設計](docs/architecture/overview.md)を埋め、下のコマンド表を実環境に合わせる。
5. 仕様・コード・検証結果を同じ変更でそろえる。全体文書3件はその場で埋め、機能テンプレートは機能ごとにコピーする。

すべての欄を最初に埋める必要はありません。`TODO:` は未決定、`対象外: 理由` は検討したうえで不要、`未実施` は検証していない状態を表します。テンプレートや記入例の内容が自動で採用されることはありません。
